# MSAL Deep Class (Microsoft Authentication Library)

## 1) What MSAL Is

MSAL (Microsoft Authentication Library) is a **client-side authentication SDK** provided by
Microsoft to obtain tokens from Azure Entra ID (formerly Azure AD) and Azure AD B2C. It
implements OAuth 2.0 and OpenID Connect flows and manages token acquisition, caching, and
renewal for client applications (SPA, mobile, desktop, and server-side apps).

In practice, MSAL is not a protocol. It is a library that **implements** OAuth2/OIDC flows
and exposes a consistent API so apps can sign users in and call protected resources.

## 2) Core Concepts

### 2.1 Accounts and Sessions

MSAL stores signed-in accounts in a cache. An account represents a user identity in a
specific tenant and is the basis for token acquisition. A user can have multiple accounts
in the cache.

### 2.2 Tokens

MSAL acquires and manages these token types:

- **ID Token** (OpenID Connect): proves who the user is.
- **Access Token** (OAuth2): allows calling protected APIs.
- **Refresh Token** (OAuth2): lets the client obtain new access tokens without re‑prompting.

### 2.3 Scopes and Resources

MSAL requests **scopes** (permissions) for resource APIs. Common examples:

- `openid`, `profile`, `email` (identity scopes)
- `api://project-hub/.default` (custom API default scopes)

### 2.4 Authority, Tenant, and Client ID

- **Authority**: the issuer URL (tenant endpoint).
- **Tenant**: the directory or B2C policy scope.
- **Client ID**: the app registration ID in Entra ID.

### 2.5 Cache and Silent Token Acquisition

MSAL attempts **silent** token acquisition first. If the token is expired or missing, it
falls back to **interactive** sign-in (redirect or popup).

### 2.6 Claims and Group/Role Information

Tokens carry claims (roles, groups, tenant, subject, scopes). Backend services can map
these claims into internal roles or permissions.

## 3) Is MSAL Similar to OAuth2?

**MSAL is not a protocol. OAuth2 is a protocol.**

MSAL implements OAuth2 and OpenID Connect flows:

- Authorization Code + PKCE (SPAs, mobile)
- Client Credentials (service-to-service)
- On-Behalf-Of (downstream API calls)

So MSAL is **built on OAuth2/OIDC**, but it is **not** the same thing. It is an SDK that
helps you execute those flows correctly and consistently on Microsoft identity platforms.

## 4) Differences: MSAL vs OAuth2

### 4.1 Type

- **OAuth2**: a protocol specification.
- **MSAL**: a library/SDK implementation of OAuth2 + OIDC.

### 4.2 Scope

- **OAuth2**: defines how to request and use tokens.
- **MSAL**: provides concrete APIs for login, token acquisition, caching, and refresh.

### 4.3 Identity Provider Specifics

- **OAuth2**: IdP‑agnostic.
- **MSAL**: optimized for Microsoft identity platforms and their conventions.

### 4.4 Token Cache and Session Handling

OAuth2 does not define how clients manage token caches. MSAL includes:

- Token storage
- Silent renewal strategies
- Account management
- Multi‑tenant support

### 4.5 Policy Integration (B2C)

MSAL includes built‑in patterns for Azure AD B2C policies (user flows, custom policies).

## 5) Typical Flow in a SPA (Angular)

1. User clicks **Sign in**.
2. MSAL redirects to the IdP.
3. IdP authenticates and returns tokens.
4. MSAL stores tokens and user account in cache.
5. HTTP interceptor attaches access tokens to API requests.
6. Tokens are silently refreshed when they expire.

## 6) How MSAL Applies to This Workspace

### Angular Project Hub (Frontend)

- Uses MSAL with redirect flow.
- Configures protected resources for `/api` and `/security`.
- MSAL interceptor attaches tokens for both APIs.

This enables:

- Project Hub API calls with `api://project-hub/.default`
- Security Service calls with `api://security-service/.default`

### Security Service (Backend)

The security-service is a **resource server**. It validates access tokens generated by the
IdP (the same tokens MSAL acquires). It does not use MSAL directly, but it depends on the
tokens produced by MSAL flows on the client side.

## 7) Common Questions

### Is MSAL required for OAuth2?

No. MSAL is one of many client libraries. You can implement OAuth2 flows manually or use
other SDKs.

### Does MSAL replace OAuth2?

No. MSAL **implements** OAuth2/OIDC for Microsoft identity. It does not replace the
protocol.

### Is MSAL secure?

Yes, when used correctly. It follows best practices like Authorization Code + PKCE for SPA
and includes safe defaults for token handling.

## 9) Glossary

- **OAuth2**: Authorization framework for delegated access.
- **OIDC**: Identity layer on top of OAuth2 (adds ID tokens).
- **MSAL**: Microsoft Authentication Library.
- **Access Token**: Token used to call protected APIs.
- **ID Token**: Token that identifies the user.
- **PKCE**: Proof Key for Code Exchange (prevents authorization code interception).
